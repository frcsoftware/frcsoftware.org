# Drivetrain（底盘驱动系统）

<ContentFigure
    width="650px"
    alt="底盘驱动系统"
    src="/learning-course/stage1/stage1a/kitbotDrivetrain.webp"
/>

Kitbot 使用四电机的 tank drive（坦克式底盘）。
坦克式底盘是一种底盘驱动系统，左右两侧分别由各自一侧的电机独立驱动。
这让机器人可以像坦克一样行驶：通过让左右两侧以不同速度转动，实现前进、后退、左转和右转。
和坦克一样，它不能横向移动。
在本阶段中，四个底盘驱动电机分别称为 `leftLeader`、`leftFollower`、`rightLeader` 和 `rightFollower`。

# Systemcore

Systemcore 是运行机器人代码的主处理器。
可以把它看作机器人的“大脑”。
电机控制器通过 CAN 端口连接到 Systemcore，而 Smart IO 支持 PWM 控制。

本阶段使用两种电机控制器：REV 的 SparkMAX 和 CTRE 的 TalonFX。

创建电机控制器对象时，需要提供实体电机控制器的 CAN Bus（CAN 总线）ID 和 CAN ID（CAN 设备 ID）。
CAN 总线指的是设备连接在 Systemcore 5 个 CAN 端口中的哪一个，或者连接在哪个 CANivore 上。
CAN ID 是为每个 CAN 设备配置的整数。
同一条 CAN 总线上的所有设备必须使用不同的 ID。
通过 CAN 总线和 CAN ID 的组合，Systemcore 就能把指令发给正确的电机控制器。
WPILib 提供了一个 `CANPort` 枚举。

# Motor Controller Configuration（电机控制器配置）

电机控制器有许多可以修改的设置，例如 ID、电机类型和限制值。
厂商会提供软件，例如 REV 的 [REV Hardware Client 2](https://docs.revrobotics.com/rev-hardware-client-2) 和 CTRE 的 [Phoenix Tuner X](https://v6.docs.ctr-electronics.com/en/stable/docs/tuner/index.html)，用于在电脑上运行和配置他们的设备。
不过，建议通过代码来配置设备，以确保所有电机控制器都配置正确。
这一点尤其有用，因为很容易忘记需要添加哪些配置以及它们的正确数值。

<Aside type="note" title="Note（备注）">
    电机控制器通常只需要配置一次，而且绝不应该在机器人主循环中周期性地配置。
    这是因为配置电机控制器通常是一个阻塞操作：机器人代码会暂停，等待电机控制器确认已经正确配置后才继续运行。
    如果在机器人启用时这样做，电机控制器将无法接收新的指令，机器人可能会以意想不到的危险方式做出反应。
</Aside>

本节只配置电机控制器的 invert（反向设置）。
这项设置决定了电机控制器收到正值指令时，电机朝哪个方向转动。
底盘驱动系统每一侧各有两个电机，因此必须确保同一侧的电机彼此同步转动。
可以让其中一个电机控制器跟随另一个来实现这一点。
这就是为什么一个电机叫 Leader（主电机），另一个叫 Follower（跟随电机）。
代码会让 Follower 听从发给 Leader 的指令。

电机控制器的配置将在 Robot 类的构造函数中完成。
配置电机控制器时，首先要创建一个电机控制器配置对象。
这个对象保存配置，因此可以修改，也可以在不同的电机控制器之间共享。

    </TabItem>

接下来，可以在配置对象上调用各种函数并传入新值，把设置从默认值改掉。
对于左侧电机，REV 代码中的反向设置为 `true`，CTRE 代码中为 `InvertedValue.Clockwise_Positive`。
这样，在输入为正值时，电机会朝着让机器人前进的方向转动。
由于底盘右侧的电机朝向相反，如果按同样的方式配置，在输入为正值时，它们会让车轮驱动机器人后退。
因此，右侧电机应配置为 `false` 或 `InvertedValue.CounterClockwise_Positive`，这样在输入为正值时，它们也会让机器人前进。

需要记住，只有把配置交给电机控制器时，设置才会真正改变。

        使用 `leaderMotor.getDeviceID()` 获取要跟随的 CAN ID，这样就只有一个可信的数据来源。
        这有助于避免错误：如果主电机的 CAN ID 改变了，代码只需要在一个地方修改。

        ```java {ctreRobot}#MotorConfigLeft
        ```

    </TabItem>
    <TabItem label = "REV">

# Arcade Drive（前进转向组合操控）

<ContentFigure
    width="564px"
    alt="前进转向组合操控"
    src="/learning-course/stage1/stage1a/arcadeDriveJoystick.webp"
/>

控制坦克式底盘的方式有好几种，本阶段使用前进转向组合操控。
前进转向组合操控使用摇杆的 y 轴控制机器人前进或后退的速度，用 x 轴控制机器人顺时针或逆时针旋转的速度。
WPILib 提供了一个名为 `DifferentialDrive` 的类，用来把摇杆输入转换为电机要执行的指令。

`DifferentialDrive` 的实例应该创建在最初构造电机控制器的代码下方。

<Tabs syncKey={REV_CTRE_CHOOSER_KEY}>
    <TabItem label="CTRE">

        ```java {ctreRobot}#DrivetrainInstance
        ```

    </TabItem>
    <TabItem label="REV">

        ```java {revRobot}#DrivetrainInstance
        ```

    </TabItem>

</Tabs>

注意，`DifferentialDrive` 构造函数的形式是 `DifferentialDrive(DoubleConsumer leftMotor, DoubleConsumer rightMotor)`。
创建时，`DifferentialDrive` 需要一个 `DoubleConsumer`，用来驱动左右两侧的电机。
`Consumer` 就是接收一个输入的函数，所以 `DoubleConsumer` 就是在调用时接收一个 double 作为输入的函数。
`motorController::setThrottle` 语法用于把电机控制器的 `setThrottle()` 函数提供给 `DifferentialDrive` 实例。
这个函数接收 -1.0 到 1.0 之间的输入，让电机以最大速度的某个百分比运行，这也称为 duty cycle（占空比）。
这样，当 `DifferentialDrive` 实例收到摇杆输入时，就可以用正确的占空比调用所提供电机控制器的 `setThrottle()` 函数。

<Aside type="note" title="Note（备注）">
    `DifferentialDrive` 实例只需要拿到 Leader 电机控制器的 `setThrottle()`
    函数，因为 Follower 电机会自动跟随。
</Aside>

# IMU

IMU（Inertial Measurement Unit，惯性测量单元）是一种传感器，能让机器人在场地上移动时准确跟踪自己的三维旋转，即 roll（横滚）、pitch（俯仰）和 yaw（偏航）。
虽然有多家厂商出售非常精确的 IMU，但本阶段使用 Systemcore 内置的 IMU。
Systemcore 的 IMU 实例应该创建在 `differentialDrive` 的下方。

# OpModes（运行模式程序）

`OpMode` 是一种类，它会向 Driver Station（操控站）注册自己，并提供名称和机器人模式（自动模式、手动操控模式或工具模式）。
这样，机器人就可以根据 Driver Station 上的选择运行不同的代码。
本阶段使用继承 `PeriodicOpMode` 的类。
继承 `PeriodicOpMode` 后，这些类会获得几个有用的函数，只有在 Driver Station 上选中该 OpMode 时才会被调用。

- `start()`：机器人从未启用切换到已启用时调用一次。
- `periodic()`：机器人启用期间反复调用。
- `end()`：机器人从已启用切换到未启用时调用一次。
- `disabledPeriodic()`：机器人未启用期间反复调用。

如果想进一步了解，可以在 [WPILib 文档](https://docs.wpilib.org/en/latest/docs/software/basic-programming/opmodes.html)中找到更多关于 OpMode 的信息。

`opmode` 文件夹下提供了两个空白的 `PeriodicOpMode`：`MyTeleop.java` 和 `MyAuto.java`。

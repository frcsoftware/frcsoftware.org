## Task 2: Setting Up

As mentioned on the previous page, PID uses sensor data to gather information about the mechanism.
This helps the PID controller determine the mechanism's current state and how to apply PID.
Therefore, `Drivetrain.java` needs information about the wheels, gearboxes, and encoders.

### Gearboxes

The second piece of information that we need to state is the gear ratio.
The kitbot's drivetrain uses gearboxes.
Gearboxes are mechanisms that motors are attached to.
They can help teams change the motor speed or torque.
The kitbot has gearboxes with a 10.71:1 gear ratio.
This means that the motor has to spin 10.71 times for the wheel to rotate once.

<Tabs syncKey={REV_CTRE_CHOOSER_KEY}>
    <TabItem label="CTRE">
    The `GEAR_RATIO` double can be added under the `WHEEL_CIRCUMFERENCE` variable.

         ```java {ctreRobot}#gearRatio

        ```
        When measuring rotations, we want to measure how many rotations the wheel has completed.
        The motors have built-in encoders, which measure the rotation of the motor's shaft.
        However, the wheel is connected to the gearbox's output shaft, which spins at a different speed than the motor's shaft.
        Therefore, we need to account for this reduction in the motor configs.
        This can be done using `Feedback.withSensorToMechanismRatio(GEAR_RATIO)`.
        In this context, `GEAR_RATIO` is the ratio between the shaft the encoder is connected to (the motor shaft) and the shaft you want to measure (the wheel shaft).

        Later in the `Drivetrain.java` file, the motor configurations are set up through the `leftConfig` and `rightConfig` objects.
        Add `Feedback.withSensorToMechanismRatio(GEAR_RATIO);` to both `leftConfig` and `rightConfig` as shown below:

### Encoders

The last piece of information that we need to provide the robot is the sensor data.
We want to know what the wheels' current state is so we can figure out if the Kitbot drivetrain has reached the set point.
To get this information, we're going to use the drivetrain encoders.

Encoders are sensors that measure how far the motor has traveled by keeping track of
the motor's rotations.
Then they report back the position.
The Kitbot has motors on the left and right sides of the drivetrain.

### PID Controllers

Now that information about the wheels, gearboxes, and encoders has been added, it's time to add PID.

To implement PID, the WPILib `PIDController` class is used.
Creating a `PIDController` object lets the `kp`, `ki`, and `kd` calculate the corrections needed based on the sensor readings.
We will be making two `PIDController` objects: `driveDistanceController` and `headingController`

- `driveDistanceController` adjusts the robot's distance
- `headingController` adjusts the robot's angle
  Under `GEAR_RATIO`, add the two objects.
  For now, the parameters can be all set to 0.
  These will be tuned later.

To make the `PIDController`s work, we have to add tolerance and enable the continuous input.

First, we need to add tolerances for both `driveDistanceController` and `headingController`.
Setting the tolerance is important because it defines the margin of error around the setpoint that is considered "close enough" to stop adjusting.

Now we have to enable the continuous input on `headingController`.
Enabling continuous input helps the `PIDController` to figure out the shortest turn to the target angle.
This prevents the motor from taking the longer way around.

In the `Drivetrain()` constructor, under `setDefaultCommand(idle())` add the tolerance and continuous input settings.

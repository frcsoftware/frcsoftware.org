## Sensors

Sensors are used to get information about the robot, such as how far it has driven or how many degrees it turned.
This is important when adding PID to the kitbot because PID uses sensor data to gather information about the mechanism.
The sensors that this stage uses are encoders and an IMU.
Before the code for encoders can be added in, there has to be some prep work.
`Drivetrain.java` needs to know the robot's wheel radius, drive gear ratio, and have access to its encoders.

### Gearboxes

The second piece of information that we need is the drivetrain's gear ratio.
The kitbot's drivetrain uses gearboxes.
Gearboxes are mechanisms that motors are attached to.
They can help teams change the motor speed or torque.

The kitbot has two gearboxes on the right and left sides of the drivetrain.
The motors are attached to one side of the gearbox.
The motor's shaft connects to the set of gears and, on the other side, the wheels are attached to the gear output shaft.

<ContentFigure
    width="650px"
    alt="Drivetrain"
    src="/learning-course/stage1/stage1c/gearboxes.webp"
/>

These gearboxes have a 10.71:1 gear ratio.
This means that the motor has to spin 10.71 times for the wheel to rotate once.

        The motors have built-in encoders, which measure the rotation of the motor's shaft.
        However, the wheel is connected to the gearbox's output shaft, which spins at a different speed than the motor's shaft.

        In this context, `GEAR_RATIO` is the ratio between the shaft the encoder is connected to (the motor shaft) and the shaft you want to measure (the wheel shaft).

        Later in the `Drivetrain.java` file, the motor configurations are set up through the `leftConfig` and `rightConfig` objects.

### Encoders

Now that the wheel size and gearboxes are known in the code, encoders can be added.
Encoders are sensors that measure how far the motor has traveled by keeping track of
the motor's rotations.
Then they report back the position.
We want to know what the wheels' current state is so we can figure out if the Kitbot drivetrain has reached the set point.
To get this information, we're going to use the drivetrain encoders.
The Kitbot's drive motors have built-in encoders.
This means that the encoders are built into the motor, which makes using the encoders in code much easier.

## IMU

An IMU (Inertial Measurement Unit) is a sensor that allows the robot to accurately track its 3D rotation (roll, pitch, and yaw) as it moves around the field.
In Stage 1B, the Systemcore’s built-in IMU was declared but it was unused.
In this stage, the IMU will be used to allow the kitbot to auto-align to the hub.

### Heading and Pose

The last two methods are `getHeading` and `setPose`.
`getHeading` gets the robot's current facing angle and sets the robot's position on the field in the simulation.
